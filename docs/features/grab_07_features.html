GRAB 0.7 adds database access for products, accounts, orders, and other information that must survive a restart.

Ready to try locally. Prepared queries, exact prices, explicit transactions, and versioned migrations now connect to the persistent GRAB server. See the runnable catalog guide.

01

SQLite

A local database file. No separate database service or C compiler for development and automated tests.

02

MariaDB

A shared database service for deployed applications. Explicit SQL contracts keep money and other values precise.

03

PostgreSQL

The same GRAB calls with a PostgreSQL adapter. Each database keeps its own SQL dialect and concurrency behavior.

RUNNABLE GRAB SYNTAX

Prepare the question. Supply the values separately.

Import data, open an authorized named connection, and prepare a fixed SQL query. Its contract declares the types going in and coming out.

use data
set shop to data.open using "shop"
set find_product to data.prepare using shop, "SELECT id, name FROM products WHERE id = :id", record {params: record {id: "integer"}, columns: record {id: "integer", name: "text"}}
set product to data.one using find_product, record {id: 42}
if product is nothing
  show "Product not found"
otherwise
  show product.name
end

1. Fixed SQL

Query structure comes from a literal in the program. Visitor input cannot become a table name, SQL command, or query fragment.

2. Bound values

:id receives the separate value 42. Even a malicious-looking text value stays data.

3. Clear results

one returns one record or nothing. query returns a list of records. Too many rows for one is an error.

What builders and visitors gain

For developers

  • One readable module API across three databases.
  • Predictable types, bounded queries, and clear errors.
  • Reusable prepared statements and connection pools.
  • Versioned schema changes with recorded checksums.

For people using the app

  • Saved information survives application restarts.
  • Account and order updates can succeed or fail together.
  • Exact currency values avoid hidden float rounding.
  • Database secrets and error details stay out of responses.

Permission comes before connection

The operator names each database in an explicit configuration file. The program cannot substitute a new host, file path, password, or connection URL.

grab run --db-config grab.data.json --allow-db shop:read-write app.grab
Database permissions
GrantAllowed
No grantNo database access. Importing the module does not grant access.
shop:readRead the configured shop database.
shop:read-writeRead and change rows; cannot change the schema.
shop:migrateExplicit maintenance runs may apply versioned schema changes. Never allowed in the web server.

File and HTTP permissions do not grant database access. Disk SQLite stays confined to its database and rollback journal (WAL/SHM and disk temporary files are refused). Remote databases require destination checks, verified TLS (unless explicitly disabled for a literal loopback IP), and a limited database account.

All together, or roll back

Transactions

Begin a transaction, run its statements, and commit explicitly. A failed statement makes it rollback-only. An unfinished request rolls back automatically.

No automatic write retries. If a connection fails during commit and the result is uncertain, report that uncertainty so the app can reconcile it.

Migrations

Apply numbered schema changes in a separate maintenance run. Lock migration execution and verify the recorded history before changing anything.

MariaDB schema changes can commit independently. A failed migration is marked dirty for reviewed recovery; the system must not promise to undo committed DDL.

Try a lasting product catalog

On Windows/amd64 or Linux/amd64 with Go 1.26 or newer, run these commands from the repository root to apply the SQLite migration, seed two products in a transaction, and start the server with a read-only database grant:

go run ./cmd/grab migrate --db-config examples/grab.data.json --allow-db shop:migrate examples/catalog_migrate.grab
go run ./cmd/grab run --db-config examples/grab.data.json --allow-db shop:read-write examples/catalog_seed.grab
go run ./cmd/grab serve --db-config examples/grab.data.json --allow-db shop:read examples/catalog_app.grab

Open http://127.0.0.1:8080/ in your browser to view the catalog (or visit /products/1, /products/2, and the /api/products JSON endpoint). Migrations are an explicit maintenance step—requests and reloads never run them—and repeating the migration or seed is safe. Product names are escaped by templates, prices use SQLite TEXT storage with explicit decimal contracts to preserve exact cents, and catalog.db stays local as a read-only browsing example (not a checkout or payment system).

Disk SQLite supports Windows/amd64 and Linux/amd64 with confined rollback journals; WAL and unsupported SQL constructs are refused. Remote servers use explicit dialect SQL and verified TLS.
