Connected applications.
Explicit boundaries.

GRAB 0.8 joins typed browser clients, external services, durable work, live notifications, and multiple server processes.

Implementation guide · November 12, 2026 · Current owner: OpenAI Codex

This is not a release-complete claim. Automated feature tests and real-service checks verify specific behavior. The specification also requires sustained 30-minute fault/load runs at 1, 2, and 4 workers and a complete acceptance record. See verification and outstanding gates.

What developers can build

01 · Fast shared data

Cache with clear limits

Memory or standalone Redis stores preserve exact GRAB values. Atomic fixed-window limits count concurrent attempts without a read-then-write race.

Developer: explicit namespaces, TTLs and independent permissions.
Visitor: repeated pages can reuse recent data; overload can be rejected predictably.

Cache guide →

02 · Browser contracts

Typed APIs and React adapters

One declared JSON contract validates requests and responses and generates deterministic TypeScript clients, including a React adapter. Exact numbers travel without silent rounding.

Developer: shared wire rules and runtime validators.
Visitor: forms and screens can handle invalid data and cancellation explicitly.

Typed API guide →

03 · External services

Verified connectors and signed webhooks

Vendored connector packages are locked by integrity hashes. Host grants, secret references, destination checks and raw-byte signature verification define the boundary.

Developer: reusable service adapters without embedding secrets in browser output.
Visitor: unauthorized or altered incoming events are rejected.

Integration guide →

04 · Durable work

Inbox and outbox transactions

SQLite, MariaDB and PostgreSQL retain accepted work. Leases, fencing, retry policy and maintenance commands make failures visible and recoverable.

Developer: commit business data and outgoing work together.
Visitor: accepted work can survive a process restart. Provider idempotency remains an explicit contract.

05 · Authorized realtime

Notify, reconnect, refetch

WebSocket channels require application authorization, exact Origin allowlists and typed JSON. Memory works locally; Redis joins notifications across processes. Expiry and queue caps bound each connection.

Developer: audience isolation and separate connect/publish grants.
Visitor: live change notices, followed by an authoritative HTTP refresh. Notifications have no durable replay guarantee.

Channel guide →

06 · Supervision and visibility

Private workers, measured operations

Run 1–32 supervised processes on consecutive loopback ports. Budgets cap aggregate pools; bounded restarts and rolling drains contain failures. OpenMetrics and OTLP are explicit opt-ins.

Developer: authenticated readiness, sanitized telemetry and predictable resource bounds.
Visitor: an external balancer can route to healthy processes while replacements start.

A complete business update

The permanent conformance fixture exercises this sequence using real GRAB handlers and network connections.

1 · VERIFYA signed webhook enters a durable inbox.
2 · COMMITOne transaction writes business data and an outbox item.
3 · NOTIFYOutbox delivery calls a separately authorized notification endpoint.
4 · REFETCHThe client receives a change notice and fetches validated HTTP state.

Resending the fixture's webhook leaves one committed business row. This demonstrates its explicit idempotency policy; it does not promise exactly-once delivery for arbitrary providers.

Limits are part of the feature

BoundaryDefault behavior
Channel traffic64 KiB messages; 100 messages/second; 16 audiences; bounded incoming and outgoing queues.
Replacement30-second worker drains. Reconnect and refetch after a socket closes. Rolling mode requires unchanged public contract bytes.
Crash loopsBounded exponential delay; more than five restarts in five minutes leaves capacity unready.
TelemetryDisabled without a grant; authenticated loopback metrics; verified-TLS trace export; 2,048 buffered spans/process.
PrivacyConfigured routes and fixed categories only. No payloads, users, tokens, SQL values or raw URLs in telemetry attributes.

What this milestone does not include

Redis Cluster/Sentinel, durable WebSocket replay, automatic cluster membership, a bundled public load balancer, automatic migrations during reload, or universal exactly-once provider effects. Durable attempts have private correlation links; the full sustained-load acceptance record remains outstanding. GRAB 0.9 VM work, native UI/compiler and CMS remain unapproved.
