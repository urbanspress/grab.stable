GRAB 0.8 is the approved next step on top of GRAB Server (0.6) and GRAB Data (0.7). Its full target adds fast Redis caching and rate limiting, typed React/TypeScript API clients, reusable third-party connectors, verified webhooks with durable retries, real-time WebSocket updates, and multi-worker scaling.

Read the full specification in specifications/GRAB-SCALE-SPEC-008.md and proposed decisions ADR-025a–ADR-025h in docs/adr/ADR-DECISION-REGISTER.md.

Progress Notice (November 12, 2026): The owner approved specification 008 and its design. Other examples below show approved target behavior still to be implemented: typed clients, connectors, durable work, channels, workers and telemetry. Full release acceptance remains pending. 1. Strict Host Configuration & Default-Deny Permissions

Proposed · grab.platform.json

Just like --db-config keeps database hosts and credentials out of GRAB code, proposed --platform-config grab.platform.json declares caches, connectors, webhooks, WebSocket channels, event stores, worker limits, and telemetry collectors in one private operator file. Secrets are referenced by host environment variable names—never hardcoded or exposed to callers.

Proposed FlagWhat It Authorizes (Default Deny Otherwise)
--allow-cache alias:read / read-write / limitRead/write cache entries or run isolated atomic rate-limit counters in one named namespace.
--allow-connector alias:operationCall one specific declared operation in a lockfile-verified connector package.
--allow-events alias:accept / workIngest verified webhooks into the durable inbox or run background inbox/outbox workers (also requires DB write grant).
--allow-channel alias:connect / publishUpgrade authorized WebSocket clients or publish notifications to authorized audiences.
--allow-telemetry aliasExport sanitized OpenTelemetry traces to one TLS-verified collector.

2. Redis Caching & Atomic Rate Limiting (use cache)

Proposed · Not Implemented

use cache keeps repeated lookups fast and protects endpoints from traffic spikes. Developers choose either redis (standalone Redis with verified TLS and ACL isolation) or memory (for local testing—never a silent fallback if Redis goes down). Rate limits run as a single atomic Redis script so counts and expirations stay accurate under load, and failures fail closed (429 when over limit, 503 if the store is down).

Proposed Syntax (Not Yet Implemented) 
use cache
set store to cache.open using "catalog"
set gate to cache.limit using store, "ip:198.51.100.2", 60, 60000
if not gate.allowed
  # Return 429 with Retry-After seconds
end
set hit to cache.get using store, "product:42"
if not hit.found
  call cache.set using store, "product:42", product, 300000
end

Developer benefits

  • Exact canonical encoding preserves integers, decimals, bytes, and nothing without float rounding.
  • Mandatory TTLs (1 ms to 7 days) and strict key/value size limits prevent runaway cache memory.
  • memory driver with an injectable test clock enables deterministic offline unit tests.

Visitor & operator benefits

  • Pages respond faster when common catalog queries are cached.
  • Abuse protection cannot silently reset to zero during a Redis outage.
  • Temporary cache/limit state is clearly separated from durable orders and ledgers.

3. Typed JSON Contracts & React/TypeScript Adapters (ADR-014)

Proposed · Not Implemented

A strict contract file (grab.api.json) describes inputs and outputs for existing GRAB routes. Handlers validate requests and responses with use api (api.input / api.respond), while a deterministic offline CLI command generates ready-to-use TypeScript types, runtime validators, a fetch client, and optional React hooks—without running npm, downloading packages, or inventing a new UI framework.

Proposed CLI Commands (Not Yet Implemented) 
grab check --api-contract grab.api.json app.grab
grab generate client --api-contract grab.api.json --out generated/shop --react
grab serve --api-contract grab.api.json --platform-config grab.platform.json app.grab

Developer benefits

  • Outputs types.ts, client.ts, validators.ts, contract.json, README, and optional react.ts.
  • Exact GrabInteger and GrabDecimal strings prevent JavaScript Number rounding on prices and IDs.
  • React hooks include {data, error, loading, refetch}, unmount cancellation, and Strict Mode safety.

Visitor & operator benefits

  • Invalid input gets clear 400/413 JSON error envelopes without leaking stack traces or secrets.
  • Same-origin defaults, explicit CORS allowlists, and CSRF rules protect cookie-authenticated mutations.
  • Generated files use an ownership manifest so existing hand-edited files are never accidentally overwritten.

4. Connector SDK, Verified Webhooks & Durable Inbox/Outbox

Proposed · Not Implemented

use connect invokes vendored, data-only connector packages locked by SHA-256 hashes in grab.connect.lock—no downloaded scripts or hidden code execution. Incoming webhooks verify raw request bytes and HMAC signatures before writing a deduplicated record to the database inbox, and outgoing API side effects queue into an outbox inside the same database transaction via use events.

Proposed Inbox Handler & Maintenance CLI (Not Yet Implemented) 
use data
use events

make on_order_paid using event
  # Business DB writes + events.enqueue share one atomic transaction
  call events.enqueue using event.transaction, "main_events", "fulfillment", "notify", record {order_id: event.payload.order_id}, "order:" joined with event.payload.order_id
  call events.complete using event.transaction, event
end
grab events inspect --store main_events --id evt_123
grab events resolve --store main_events --id evt_123 --outcome not-delivered --reason "verified with provider"
grab events retry --store main_events --id evt_123 --reason "safe manual replay"

Developer benefits

  • Reusable provider-neutral package format with a fake-provider test harness and signature test vectors.
  • At-least-once delivery with lease fencing tokens prevents two workers from processing the same item concurrently.
  • Unsafe external writes with uncertain network results move to uncertain for safe reconciliation instead of blind double-charging.

Visitor & operator benefits

  • Forged, tampered, expired, or mismatched-body webhooks are rejected with 401/409 before touching app state.
  • Accepted webhooks never get lost in RAM: they commit to SQLite/MariaDB/PostgreSQL before returning 202.
  • Durable retry backoff (up to 24h) and dead-letter inspection prevent silent lost orders.

5. Authorized WebSockets (use sockets) & 6. Multi-Worker Scaling

Proposed · Not Implemented

use sockets adds live browser updates over reserved GET WebSocket paths. Every connection runs an explicit authorize check before upgrade, validates browser Origin headers, enforces strict message/queue limits, and broadcasts through memory (single worker) or standalone Redis pub/sub (multi-worker). Meanwhile, grab serve --workers N --worker-base-port P supervises up to 32 worker processes behind your reverse proxy, with rolling reloads, OpenMetrics metrics, and opt-in OTLP traces.

Proposed Multi-Worker Launch (Not Yet Implemented) 
grab serve --workers 4 --worker-base-port 8100 --platform-config grab.platform.json --db-config grab.data.json app.grab

WebSocket safety & clarity

  • Text JSON messages are contract-validated; oversized or slow connections close cleanly with RFC 6455 codes.
  • Pub/sub is an optimization hint—reconnecting clients refetch authoritative state over typed HTTP.
  • Auth expiration closes the socket rather than letting stale sessions linger.

Scaling & observability

  • Startup verifies identical code/config/lock hashes and ensures aggregate DB/Redis pools stay within budget.
  • Loopback OpenMetrics listener (disabled by default) and opt-in TLS OTLP traces drop PII, payloads, and secrets.
  • Release requires passing real Redis, MariaDB, PostgreSQL, race, and 30-minute fault/load tests.

Explicitly Excluded from GRAB 0.8

  • No browser compiler, GRAB UI framework, or CMS: React/TypeScript output is strictly typed API client glue; GrabLab, Grex/Grex JS, and browser UI remain Post-1.0.
  • No bytecode VM or IR yet: Optimization and the semantic-equivalent VM belong to GRAB 0.9.
  • No arbitrary plugin execution or package registry: Connectors are vendored, data-only, and SHA-256 locked.
  • No Redis Cluster/Sentinel discovery, general cron scheduler, or auto-deployment: Multi-host scaling uses supervised instances behind an external load balancer.
