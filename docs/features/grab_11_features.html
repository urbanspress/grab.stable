GRAB 1.1 (v1.1.0) · Additive-Only Security & Runtime Release

Native Cryptography, Capability Env & Opt-In Script CSP

Production-ready security building blocks for logins, sessions, encrypted OAuth2 tokens, explicit environment secrets, and local Grex JS interactive admin pages—with 100% backward compatibility across GRAB 1.0.

Why GRAB 1.1 matters in plain English: Building modern logins and admin dashboards without external shell commands requires rock-solid password hashing, cryptographically random session tokens, authenticated encryption, locked-down secrets, and a browser Content Security Policy that lets your own compiled JavaScript run without opening the door to cross-site scripting. GRAB 1.1 builds all three directly into the language and server.

The Three Pillars of GRAB 1.1

Pillar 1 · use crypto

8 Built-In Cryptographic Primitives

use crypto ships native Argon2id password hashing and constant-time verification, bounded crypto/rand URL-safe and hex token generators, SHA-256 hex & OAuth2 PKCE S256 digests, and AES-256-GCM authenticated encryption at rest.

Visitor & Owner Benefit: Passwords use memory-hard Argon2id salts, tokens are unpredictable, and OAuth refresh tokens stay encrypted in the database automatically.

Pillar 2 · use env + --allow-env

Default-Deny Environment Variables

use env provides env.get and env.has across grab run and grab serve. Any variable not explicitly granted by --allow-env <VAR[,VAR...]> fails closed immediately with GRAB-E401 and never leaks host secrets.

Developer & Operator Benefit: Keep API keys and encryption keys out of source files and grant only the exact variable names each app needs—propagated safely to multi-worker pools.

Pillar 3 · grab serve --allow-scripts

Opt-In Strict Self-Hosted Scripts

grab serve keeps strict script-src 'none' on by default. Passing --allow-scripts emits script-src 'self' while keeping object-src 'none' and blocking unsafe-eval and inline scripts.

Storefront & Admin Benefit: Local Grex JS v1.0.0 interactive admin bundles served via server.asset run smoothly under a tight browser security boundary.

SemVer 2.0.0 · ADR-027c

100% AST, Bytecode VM & MCP Parity

Every function in crypto and env runs identically across --engine=ast, --engine=vm, and --engine=auto, while grab mcp validates and formats new syntax offline with zero secret exposure.

Upgrade Confidence: Drop-in upgrade from v1.0.x with zero breaking changes to existing routes, templates, or manifest schemas.

Complete Auth & PKCE Example in GRAB 1.1

use crypto
use env
use server

# Run with: grab serve --allow-env AEAD_KEY --allow-scripts --static /static/=./public app.grab
route "POST" "/login" using req
  set pw_hash to crypto.hash_password using "admin-passphrase"
  set ok to crypto.verify_password using "admin-passphrase", pw_hash
  set raw_session to crypto.random_urlsafe using 32
  set session_hash to crypto.sha256_hex using raw_session
  set pkce_challenge to crypto.sha256_base64url using raw_session
  set key to env.get using "AEAD_KEY"
  set encrypted_oauth to crypto.encrypt_aead using "oauth_refresh_token", key
  give back server.json using 200, record {ok: ok, session_hash: session_hash, pkce: pkce_challenge, sealed: encrypted_oauth}
end
