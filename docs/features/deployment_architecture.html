ADR-005 & ADR-017 · Production Reverse-Proxy Standard

Hardened edge in front.
Warm GRAB workers behind.

GRAB is built like a persistent application engine (similar to Go or Swoole), not a script that boots from scratch on every page view. In production, a reverse-proxy edge (Caddy, Nginx + Certbot, or Cloudflare Tunnel) handles automatic SSL/TLS termination while GRAB runs inside a locked-down, non-root container on private loopback ports—never running as root or touching certificates directly.

Reference rules for engineers and AI agents live in docs/DEPLOYMENT.md and docs/adr/ADR-DECISION-REGISTER.md.

Every visitor request passes through automatic edge TLS termination and proxy filtering before reaching GRAB's private worker ports, which talk to stateful data stores over an isolated internal network.

Why This Architecture Works

Bulletproof Security (ADR-005 & ADR-017)

  • Never root, never touches certs: grab serve never runs as root and never manages SSL certificates directly—automatic HTTPS stays cleanly at the edge proxy.
  • Private loopback by default: GRAB refuses public interfaces unless --allow-public is explicitly passed, keeping app ports invisible to the internet behind the edge proxy (ADR-005).
  • Zero spoofed client headers: --trusted-proxy 127.0.0.1,::1 (or explicit proxy CIDR) ensures GRAB only trusts forwarding headers from your proxy, never raw visitor headers.
  • Strict server/browser separation (ADR-017): Database credentials, host manifests, and error stacks stay on the server; templates context-escape HTML automatically.
  • Default-deny capabilities: File, network, and database access stay off unless granted explicitly via --allow-read, --allow-net, and --allow-db.
  • Container blast-radius containment: Running GRAB as a non-root user inside a read-only container with dropped capabilities limits damage even if an external dependency misbehaves.

Maximum Swoole / Go-Class Speed

  • Zero cold starts: PreparedApp lexes, parses, validates contracts, and checks templates once at startup—requests skip all parsing overhead.
  • Warm pools across requests: Database pools (GRAB 0.7) and proposed Redis pools (GRAB 0.8) stay open across requests inside each application generation.
  • Predictable backpressure: Built-in --max-concurrency and --max-queue limits shed excess spikes cleanly with 503 instead of crashing under load.
  • Rolling reloads via probes: Nginx and container orchestrators check /_health and /_ready so draining workers finish active requests before shutting down.
  • Static offload: Nginx serves CSS, JS, and media directly at wire speed, leaving GRAB workers free for dynamic routes and JSON APIs.

Automatic SSL/TLS Termination at the Edge

Per ADR-005 and ADR-017, the core GRAB runtime (grab serve) never runs as root and never manages SSL certificates directly. Automatic zero-config HTTPS (Let's Encrypt / ZeroSSL and on-demand custom-domain TLS) lives cleanly at the reverse-proxy edge, forwarding clean HTTP and WebSocket traffic to GRAB's private worker ports (127.0.0.1:8765–8772):

Edge Proxy Option How HTTPS / Certificates Work Best Fit
1. Caddy (Recommended) Automatic in-memory Let's Encrypt & ZeroSSL certificates with zero cron jobs, plus built-in on-demand TLS for custom domains. Default Choice
Zero-config HTTPS & future Gashboard / GrabLab sites.
2. Nginx + Certbot Battle-tested reverse proxy paired with automated Certbot ACME renewals, high-throughput static caching, and custom rate-limit tuning. Enterprise / Custom Ops
Teams already standardized on Nginx configs.
3. Cloudflare Tunnel Outbound-only encrypted tunnel (cloudflared) with Cloudflare terminating TLS at the global edge—zero inbound server ports opened. Zero-Inbound Hosts
Home labs, private VPCs, or DDoS-shielded apps.

Two-Stage Deployment Path

Implementation status boundary: Stage 1 (and single-worker --addr 127.0.0.1:8765 --trusted-proxy) works today in GRAB 0.6 & 0.7. Multi-worker --workers and Redis belong to GRAB 0.8 (specification in review), and packaged docker-compose.yml / grab deploy belong to GRAB 1.0 & GrabLab / Gashboard (planned, not yet approved).

Stage 1: Local Development on Windows (Live Today)

Zero Docker or Nginx setup needed while building. Run directly on 127.0.0.1:8080 with hot source reload and local SQLite: 

# Preview an app locally (GRAB 0.6)
go run ./cmd/grab serve --reload examples/server_app.grab

# Preview the SQLite catalog locally (GRAB 0.7)
go run ./cmd/grab serve --db-config examples/grab.data.json --allow-db shop:read examples/catalog_app.grab

# Single-worker private Nginx proxy bind (GRAB 0.6/0.7)
go run ./cmd/grab serve --addr 127.0.0.1:8765 --trusted-proxy 127.0.0.1,::1 --log-format json --diagnostics production examples/server_app.grab

Stage 2: Live Production docker-compose.yml (GRAB 1.0 & GrabLab Target)

Illustrative target layout pairing an edge proxy (Caddy recommended for automatic SSL, Nginx + Certbot, or Cloudflare Tunnel) with a hardened non-root Griss / GRAB container, private multi-worker ports, Redis, and PostgreSQL/MariaDB: 

# Conceptual target for GRAB 1.0 / GrabLab (planned)
services:
  edge-proxy:
    image: caddy:2-alpine          # Or Nginx + Certbot / Cloudflare Tunnel
    ports: ["80:80", "443:443"]   # Automatic Let's Encrypt / ZeroSSL HTTPS
    # Forwards clean HTTP/WebSocket traffic to Griss on 127.0.0.1:8765-8772, checks /_ready

  griss-app:
    user: "65532:65532"            # Non-root UID (never manages TLS certs)
    read_only: true                # Immutable rootfs
    cap_drop: ["ALL"]              # Minimal Linux caps
    # Runs Griss workers on private ports 8765-8772
    # Connects privately to Redis (0.8) & Postgres/MariaDB (0.7)
