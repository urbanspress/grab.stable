Native Cryptography, Capability Env & Opt-In Script CSP

Production-Grade Security Primitives for Authentication, Encrypted OAuth2/PKCE & Interactive Grex JS Pages

GRAB 1.1 adds production-grade password hashing, cryptographic tokens, SHA-256/PKCE digests, AES-256-GCM encryption at rest, default-deny environment variables, and opt-in script CSP while keeping 100% compatibility across every existing GRAB 1.0 application.

💡 Everyday Metaphor: The Vault Door & Keycard Turnstile

Imagine upgrading a boutique store with a bank-grade steel vault (`use crypto`), badge-only keycards for the back office (`use env --allow-env`), and a glass security vestibule that lets your own verified cash-register displays run safely while keeping every outside script locked out (`grab serve --allow-scripts`). Storefront pages load fast, secrets never wander into logs, and customer logins meet modern banking security automatically.

1 The Customer Browsing & Buying Experience Walkthrough

How this milestone elevates what the online shopper sees on their screen and what the GRAB platform guarantees behind the scenes.

👁 Frontend: What the Shopper Sees
Bank-Grade Password Protection

Customer and admin passwords are protected with memory-hard Argon2id hashing and random salts (`crypto.hash_password` / `crypto.verify_password`) — never reversible or stored in plain text.

Interactive Zero-Bloat Admin UIs

Passing `--allow-scripts` lets your own local Grex JS bundles (`script-src 'self'`) power instant, snappy admin dashboards while still blocking inline and third-party scripts.

Safe Social Login (OAuth2 PKCE)

Built-in `crypto.sha256_base64url` and `crypto.random_urlsafe` power tamper-proof OAuth2 PKCE logins without unsafe external packages.

Zero Leakage Guarantee

Secrets live in approved environment variables (`--allow-env`) and encrypted cookies/tokens (`crypto.encrypt_aead`) rather than hardcoded source files.

⚙ Backend: What Grisp & GRAB Do
8 Native Cryptographic Primitives

`use crypto` provides Argon2id hashing/verify, `crypto/rand` URL-safe/hex tokens (bounded `16..64` bytes), SHA-256 hex/base64url, and AES-256-GCM AEAD encryption across both AST and Bytecode VM.

Default-Deny Environment Security

`use env` (`env.get` / `env.has`) fails closed with `GRAB-E401` unless explicitly allowlisted with `--allow-env `, and forwards approved vars cleanly to multi-worker processes.

Strict Script CSP Opt-In

`grab serve` retains `script-src 'none'` by default and upgrades strictly to `script-src 'self'` (keeping `object-src 'none'`, zero `unsafe-eval`) only when `--allow-scripts` is passed.

100% AST/VM Differential Parity

Every `crypto.*` and `env.*` function runs identically across `--engine=ast`, `--engine=vm`, and `--engine=auto`, verified alongside MCP `grab_check` offline validation.

4 Real-World Code in Action
Production Auth & PKCE Session Flow in GRAB 1.1
use crypto
use env

set aead_key to env.get using "SESSION_AEAD_KEY"
set pw_hash to crypto.hash_password using "customer-passphrase"
set verified to crypto.verify_password using "customer-passphrase", pw_hash

set session_id to crypto.random_urlsafe using 32
set session_digest to crypto.sha256_hex using session_id
set pkce_challenge to crypto.sha256_base64url using session_id
set sealed_oauth to crypto.encrypt_aead using "oauth_refresh_token", aead_key
set plain_oauth to crypto.decrypt_aead using sealed_oauth, aead_key
