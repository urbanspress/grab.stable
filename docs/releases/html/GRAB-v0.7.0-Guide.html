Unified Database Access (SQLite, MariaDB, PostgreSQL)

The Tamper-Proof Ledger: Strict SQL, Scoped Transactions & Zero Lost Orders

GRAB 0.7 adds enterprise database access (`use data`) across SQLite, MariaDB, and PostgreSQL, enforcing strict literal prepared SQL, scoped atomic transactions, and zero SQL injection.

💡 Everyday Metaphor: The Armored Bank Ledger

Imagine a bank ledger written in indelible duplicate ink. When a customer buys the last jacket in stock, three things must happen together: stock drops from 1 to 0, the customer's payment is logged, and a shipment order is created. If the power cuts out midway, an unhardened system might take the money without saving the order. GRAB 0.7 enforces atomic transactions: either all three steps finish together, or everything cleanly rolls back with zero ghost orders.

👁 Frontend: What the Shopper Sees
Zero Double-Sold Inventory

When the last item sells out, inventory updates atomically. Two simultaneous shoppers will never both buy the final unit.

Bulletproof Order Records

Every successful checkout creates a guaranteed database order record with exact currency totals.

Total Payment Safety

If a payment gateway times out, the cart status and reserved inventory automatically revert in milliseconds.

Instant Catalog Searches

Indexed database queries return product results in single-digit milliseconds without lagging the storefront.

⚙ Backend: What Grisp & GRAB Do
Strict Literal Prepared SQL

SQL statements must be string literals; dynamic string concatenation is rejected at compile time (SQL injection impossible).

Scoped Atomic Transactions

`data.begin` creates an isolated transaction (`tx`); `tx.commit` seals changes, `tx.rollback` safely reverts on errors.

Tri-Engine Unified API

Write identical GRAB database logic whether running on embedded pure-Go SQLite, MariaDB, or PostgreSQL.

Automated Migration CLI

`grab migrate` manages versioned database schema upgrades safely with migration locks.

4 Real-World Code in Action
Atomic Checkout & Stock Reservation in GRAB 0.7
use data

make checkout_item using db, item_id, user_id
  set tx to data.begin using db
  try
    set item to data.query_one using tx,
      "SELECT id, price, stock FROM products WHERE id = ? FOR UPDATE", [item_id]
    if item.stock < 1
      raise record {code: "OUT_OF_STOCK", message: "Item is sold out!"}
    end
    data.execute using tx,
      "UPDATE products SET stock = stock - 1 WHERE id = ?", [item_id]
    data.execute using tx,
      "INSERT INTO orders (user_id, product_id, price) VALUES (?, ?, ?)",
      [user_id, item.id, item.price]
    data.commit using tx
    give back record {success: yes}
  catch err
    data.rollback using tx
    give back record {success: no, error: err.message}
  end
end
